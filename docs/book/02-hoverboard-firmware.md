# Глава 2. Прошивка платы гироскутера (EFeru FOC)

> **Цель главы:** понять, что делает прошивка
> [hoverboard-firmware-hack-FOC](https://github.com/EFeru/hoverboard-firmware-hack-FOC),
> какие её настройки важны для нашего робота, как её собрать и залить.

Код лежит в git-подмодуле `firmware/hoverboard-firmware-hack-FOC/`. Если папка
пустая:

```bash
git submodule update --init
```

Мы **не меняем** код подмодуля — только выбираем вариант сборки и передаём
настройки флагами. Так подмодуль легко обновлять.

## 2.1. Что делает плата и почему её перепрошивают

Заводская плата гироскутера (STM32F103 + два трёхфазных моста) умеет только
балансировать. Прошивка EFeru превращает её в универсальный контроллер двух
BLDC-моторов:

- **FOC** (field-oriented control) — тихое, плавное управление моторами;
- приём команд по UART, PWM, PPM, ADC или от нунчака — выбирается *вариантом*;
- телеметрия обратно: обороты колёс, напряжение батареи, температура;
- защиты: ограничение тока, таймаут потери команд, отключение по бездействию.

Нам нужен вариант **`VARIANT_USART`**: управление и телеметрия по UART.

## 2.2. Интерфейс UART: кадры команд и телеметрии

Плата и ESP32 обмениваются двоичными кадрами. Все поля — 16 бит,
little-endian, начало кадра — `0xABCD`, в конце — XOR всех предыдущих слов.

**Команда (ESP32 → плата), 8 байт** — структура `SerialCommand`:

| Поле | Тип | Смысл |
|---|---|---|
| `start` | u16 | `0xABCD` |
| `steer` | i16 | поворот, −1000…1000 |
| `speed` | i16 | скорость, −1000…1000 |
| `checksum` | u16 | `start ^ steer ^ speed` |

**Телеметрия (плата → ESP32), 18 байт** — структура `SerialFeedback`
(`Src/main.c`), шлётся каждые 10 мс:

| Поле | Смысл |
|---|---|
| `start` | `0xABCD` |
| `cmd1`, `cmd2` | принятые входы (для отладки) |
| `speedR_meas`, `speedL_meas` | **обороты мотор-колёс, об/мин** |
| `batVoltage` | напряжение батареи (×100 В) |
| `boardTemp` | температура платы (×10 °C) |
| `cmdLed` | состояние светодиодов сайдборда |
| `checksum` | XOR всех полей выше |

> **⚠ Внимание: `ENABLE_ODOMETRY`.** Если в `Inc/config.h` раскомментировать
> `ENABLE_ODOMETRY`, в кадр добавятся два поля (`wheelR_cnt`, `wheelL_cnt`) и он
> станет 22 байта. Разборщик в ESP32 (`hbReadFeedback`, гл. 3) ждёт ровно 18 —
> телеметрия перестанет приниматься. Оставьте опцию выключенной или правьте
> обе стороны.

### Как плата смешивает steer и speed

Функция `mixerFcn` (`Src/util.c`) превращает пару входов в команды колёс:

```c
prodSpeed = speed * SPEED_COEFFICIENT;   // по умолчанию 1.0
prodSteer = steer * STEER_COEFFICIENT;   // по умолчанию 0.5
cmdR = prodSpeed - prodSteer;
cmdL = prodSpeed + prodSteer;
```

Значит, `steer > 0` ускоряет **левое** колесо — робот поворачивает вправо (по
часовой стрелке). ESP32 учитывает это знаком (гл. 3, `hbUpdate`).

## 2.3. Настройки, которые важны для нашего робота

Все настройки — в `Inc/config.h`. Пройдёмся только по нужным.

### Вариант сборки

В `platformio.ini` подмодуля уже есть окружение `[env:VARIANT_USART]` — оно
передаёт `-D VARIANT_USART`. В `config.h` раскомментировать ничего не нужно.

### Какой кабель сайдборда (USART2 или USART3)

Секция `VARIANT_USART SETTINGS`:

```c
#define CONTROL_SERIAL_USART2  0    // левый кабель сайдборда
#define FEEDBACK_SERIAL_USART2      // телеметрия туда же
// #define CONTROL_SERIAL_USART3  0  // правый кабель
// #define FEEDBACK_SERIAL_USART3
```

По умолчанию команды и телеметрия идут через **USART2 — левый (длинный) кабель
сайдборда**. Именно его подключают к ESP32 (GPIO 17/18). Если удобнее правый
кабель — раскомментируйте строки `USART3` и закомментируйте `USART2`
(одновременно на одном порту управление и I2C/нунчак работать не могут).

### Скорость UART — главная ловушка

```c
#ifndef USART2_BAUD
  #define USART2_BAUD 115200
#endif
```

По умолчанию плата работает на **115200 бод**, а прошивка ESP32 — на
`HB_BAUD = 1000000` (`firmware/esp32_bridge/include/config.h`). **В таком
виде связь не заработает.** Выберите одно значение и выставьте его с обеих
сторон. Так как скорость обёрнута в `#ifndef`, её можно передать флагом, не
трогая код подмодуля. В `platformio.ini` подмодуля, окружение `VARIANT_USART`:

```ini
build_flags =
    ...
    -D VARIANT_USART
    -DUSART2_BAUD=1000000
    -DUSART3_BAUD=1000000
```

Либо наоборот — оставить плату на 115200 и поменять `HB_BAUD` в ESP32. Кадр
телеметрии 18 байт каждые 10 мс — это 1800 байт/с, 115200 бод (~11 КБ/с)
справляются с запасом; 1 Мбод даёт меньшую задержку, но требователен к
качеству проводов. Скрипт `scripts/hardware_bringup.sh check` сравнивает
обе стороны и подскажет, если они расходятся.

> Правка `platformio.ini` подмодуля — это локальное изменение внутри
> подмодуля. Его не потеряйте при `git submodule update`; запишите в
> заметки или держите патч рядом.

### Режим управления

```c
#define CTRL_TYP_SEL  FOC_CTRL     // тип: COM_CTRL, SIN_CTRL, FOC_CTRL
#define CTRL_MOD_REQ  VLT_MODE     // режим: OPEN, VLT, SPD, TRQ
```

| Режим | Что значит `speed = 500` | Плюсы / минусы для робота |
|---|---|---|
| `VLT_MODE` (по умолч.) | ~половина напряжения на мотор | быстрый отклик; скорость зависит от нагрузки и заряда |
| `SPD_MODE` | цель в об/мин, замкнутый регулятор | скорость не плывёт под нагрузкой; нужно пересчитать коэффициенты в ESP32 |
| `TRQ_MODE` | момент | для робота неудобен |

ESP32 сейчас рассчитан на `VLT_MODE`: коэффициенты 400 и 600 в `hbUpdate`
подобраны вручную. Обратная связь по скорости всё равно есть — одометрия
считается по **измеренным** оборотам, а SLAM поправляет позу. Если робот в
навигации «не дотягивает» до заданной скорости, `SPD_MODE` — первый кандидат
на улучшение (см. упражнение в конце главы).

### Ограничения и защиты

| Параметр | По умолчанию | Комментарий |
|---|---|---|
| `I_MOT_MAX` | 15 А | ток одного мотора; для лёгкого робота можно снизить до 8–10 А — мягче старт, меньше риск |
| `I_DC_MAX` | 17 А | должно быть `I_MOT_MAX + 2` |
| `N_MOT_MAX` | 1000 об/мин | 1000 об/мин × π × 0.16 м ≈ 8.4 м/с — для робота с запасом |
| `FIELD_WEAK_ENA` | 0 | ослабление поля для высоких скоростей — не нужно |
| `SERIAL_TIMEOUT` | 160 (≈0.8 с) | нет команд — плата останавливает моторы и пищит |
| `INACTIVITY_TIMEOUT` | 8 мин | автоотключение при бездействии |
| `BAT_CELLS` | 10 | 10S-аккумулятор гироскутера, 36 В |

Защита от потери связи двухступенчатая: ESP32 обнуляет команду через 300 мс,
плата — через ~0.8 с без кадров.

### Направление вращения

`INVERT_L_DIRECTION` / `INVERT_R_DIRECTION` в секции варианта по умолчанию
выключены. Левый мотор стоит зеркально, поэтому его об/мин приходят с
обратным знаком — ESP32 это компенсирует (`vl = -speedL_meas`). Если после
сборки робот едет назад вместо вперёд, правьте **одно место**: либо флаги
инверсии здесь, либо знаки в ESP32 — но не оба.

## 2.4. Сборка и прошивка

Нужен программатор **ST-Link V2** и PlatformIO.

### Подключение программатора

На плате гироскутера есть 4-контактный разъём SWD с выводами `3.3V`, `SWCLK`,
`GND`, `SWDIO` (порядок зависит от ревизии платы — сверяйтесь с надписями на
плате, а не с чужой фотографией). Подключите ST-Link к нему **при отключённой батарее**: плату питает
3.3 В программатора.

> **⚠ Внимание.** Не подключайте батарею, пока подключён ST-Link с питанием
> 3.3 В, и никогда не соединяйте 15 В сайдборд-кабеля с ESP32 или ST-Link.

### Снятие защиты от чтения (один раз)

Заводская прошивка защищена (read-out protection). Перед первой прошивкой
защиту снимают — это стирает чип. Через OpenOCD:

```bash
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
        -c "init; reset halt; stm32f1x unlock 0; reset run; shutdown"
```

(или через STM32 ST-LINK Utility / STM32CubeProgrammer в Windows). Подробности —
в wiki проекта EFeru.

### Сборка и заливка

```bash
cd firmware/hoverboard-firmware-hack-FOC
pio run -e VARIANT_USART               # только сборка
pio run -e VARIANT_USART -t upload     # сборка + прошивка через ST-Link
```

После прошивки: отключите ST-Link, подключите батарею, нажмите кнопку
питания. Плата издаёт короткий сигнал включения. Длинные/повторяющиеся писки
— это коды ошибок (батарея, датчики Холла, таймаут команды) — их расшифровка
в README подмодуля. Писк «нет команд» сразу после включения нормален, пока не
подключён ESP32.

## 2.5. Проверка без ESP32

Плату можно проверить USB-UART-адаптером на 3.3 В: подключите `RX` адаптера к
`TX` левого кабеля, землю — к `GND`, откройте порт на выбранной скорости и
покрутите колесо рукой. В потоке байт каждые 10 мс должна появляться
последовательность `CD AB …` — это начало кадра `0xABCD` в little-endian.

## 2.6. Итог: чек-лист прошивки платы

- [ ] Подмодуль скачан, собирается окружение `VARIANT_USART`.
- [ ] Скорость UART одинакова на плате (`USART2_BAUD`) и в ESP32 (`HB_BAUD`).
- [ ] Используемый кабель сайдборда совпадает с `CONTROL_SERIAL_USART*`.
- [ ] `ENABLE_ODOMETRY` выключен (или разборщик ESP32 доработан).
- [ ] Защита от чтения снята, прошивка залита, плата включается.
- [ ] 15 В сайдборд-кабеля изолированы.

> **✎ Упражнение.** Переведите плату в `SPD_MODE`. Тогда `speed` — это об/мин
> колеса. Выведите новый коэффициент для `hbUpdate`: сколько единиц `speed`
> соответствует 1 м/с при диаметре 0.16 м? (Ответ: 60 / (π·0.16) ≈ 119.4.)
> Учтите, что `steer` проходит через `STEER_COEFFICIENT = 0.5`.
